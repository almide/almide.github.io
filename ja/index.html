Almide · プログラミング言語 · 1.0 より前

AIが書いたコードを、より安全にするために作っている言語。

AIエージェントが書くコードは、もう自分には全部は読めません。だから安全性はコンパイラの側から出したい。そして、そのコンパイラにも自分の採点はさせません。

数字は公開リポジトリのコミット 8ce6254（台帳の日付は 2026-11-08）時点のものです。325 バイトは 0.69.0 で wasm-opt なしの値です。これからも動きます。

01 — なぜ作っているか

エージェントが書いたものを、もう全部は読めません。

今は、自分のコードの多くをAIエージェントが書いています。近いうちに多くの人がそうなると思いますし、レビューはその量に追いつきません。

だから、安全性のより多くの部分がコンパイラから出てきて、誰かが丁寧に読むことに頼る部分が減る言語が欲しかった。自分で書いていないコードでも、頼れるものが欲しかったのです。

AIに書いてほしい言語はRustだと思います。でも正直、自分はRustが得意ではなく、所有権には最後まで慣れませんでした。Almideは、あの種類の安全性を保ったまま、人にもエージェントにも所有権の部分を書かせない、という試みです。

静的型付きで、ネイティブコードへはRustを経由してコンパイルし、WebAssemblyは直接出力します。Option と Result、網羅的なパターンマッチ、明示的なエフェクト宣言があります。

02 — 間違えようがない

所有権は書きません。コンパイラが推論します。

type Order = { id: Int, items: List[String], total: Int }

fn large(orders: List[Order]) -> List[Order] =
  orders |> list.filter((o) => o.total > 500)

fn main() -> Unit = {
  let orders: List[Order] = [
    { id: 1, items: ["pen", "ink"], total: 260 },
    { id: 2, items: ["desk"], total: 900 },
  ]
  let big = large(orders)
  println("${list.len(orders)} orders, ${list.len(big)} large")
  for o in orders {
    println("${o.id}: ${list.join(o.items, ", ")}")
  }
}
$ almide run orders.almd --target wasm
2 orders, 1 large
1: pen, ink
2: desk

orders は large に渡したあと、ループでもう一度使っています。ソースのどこにも、ムーブ・借用・コピーのどれなのかは書かれていません。ライフタイムも free もありません。

ヒープ上の値がどこで作られ、共有され、消費されるかは、コンパイラがPerceus式の推論で割り出します。2つのターゲットは、その結果を別々のやり方で実行します。ネイティブの出力はRustで、解放はRust自身のdropが行います。Wasmは参照カウントを使います。

代償。コピーも参照カウントの操作も、実際には起きています。ソースのどこで起きるのかが見えないだけです。Rustなら .clone() が目に見えます。ここでは見えません。これについて、まだ良い答えを持っていません。

03 — いちばん大事にしている部分

コンパイラに、自分の採点はさせません。

自分は、自分のコンパイラを信用していません。AIエージェントと一緒に作ったものを、どうして信用できるでしょうか。

Wasmをビルドするたびに、コンパイラは自分がやったことの証拠を書き出さなければなりません。値を共有したり解放したりしたすべての場所、検査したすべての配列の添字です。その証拠を別のプログラムが読みます。つじつまが合わなければ、出力ファイルはできません。

拒否は、あなたのバグではありません。コンパイラのバグです。ビルドはそう報告します。

error[certificate-rejected]: app.almd: almide-verify judged this build's
certificate and did not accept it (exit 1)
  app.wasm was not written: the build's own certificate does not hold,
  which is a compiler bug — please report it

一部を省略しています。1行目のあとに、検証器自身の報告が続きます。

04 — そこで考えた

検査器にもバグはありえます。だから4つあります。

検査器が1つだけなら、信頼の置き場所が移るだけです。この4つは作り方がそれぞれ違うので、同じ間違いがすべてに入り込むことは起きにくくなっています。検査される証拠とあわせて、このプロジェクトではこれを Trust Spine（信頼の背骨）と呼んでいます。

1

Proofcore

Rocq の証明カーネル

検査器は、証明支援系 Rocq の中で定義され、証明されています。その判定は、証明を検査するカーネル自身に計算させることができます。

CI で動く
2

Proofcast

証明から生成した検査器

同じ証明済みの検査器を、Rocq の外へ独立したプログラムとして送り出したものです。テスト全体にかけられる速さで動きます。

CI で動く
3

Buildgate

Rust で手書きした検証器

almide-verify。独立して書いたコードで、証明はされていません。コンパイラと一緒に配布され、あなたのビルドを実際に止めるのはこれです。

手元のマシンで動く
4

Byteanchor

できあがったファイルを開くツール

最終的な .wasm をデコードし、記録された境界チェックと初期化の一つ一つを、それが指している命令と突き合わせます。そこにないコードについての証拠は通りません。

CI で動く

CIでは、Proofcore・Proofcast・Buildgate の3つが、テスト用のすべてのプログラムのすべての証拠について、同じ判定を出さなければなりません。この仕組みでの拒否は、自分のコンパイラの実際のミスコンパイルをすでに1つ捕まえています。

証明は、リポジトリにある46個のRocqファイルです。対象は検査器とそのモデルで、コンパイラではありません。

05 — コードが間違っていたとき

エラーが、何を直せばいいかを教えます。

エージェントは間違えます。大事なのは、そのあと何が起きるかです。ほかの言語を学んだエージェントは items.length と書きます。

error[E013]: no field 'length' on list
  --> app.almd:3:14
  in field access .length
  here: println("${items.length}")
  hint: Almide values have no fields — use the `list` stdlib module.
  try: (machine-applicable — `almide fix` applies it)
      list.len(items)
$ almide fix app.almd
  Applied 1 machine-applicable fix-it(s) from diagnostics: E013 at line 3

これは機械的に直せるので、ツールが適用します。関数名の打ち間違いは違います。

error[E002]: undefined function 'string.lenn'
  hint: Did you mean `string.len`?

$ almide fix app.almd
1 diagnostic(s) have `try:` snippets that need manual application:
  [E002] app.almd:3:14  undefined function 'string.lenn' (maybe-incorrect)

0.69.0 のコンパイラ出力です。一部を省略しています。

こちらは、書き手が何を意図したかについての推測です。だから候補のままにします。機械的な修復と、意図についての判断との境目を、ツールの中で見えるようにしておきたいと考えています。

06 — 出荷されない間違い

場合分けの書き忘れは、コンパイルエラーです。失敗の無視も同じです。

エージェントの編集でいちばんよく見る間違いは、型にバリアントを足して、それを処理すべき場所を1つ見落とすことです。

type Shape =
  | Circle(Float)
  | Rect(Float, Float)
  | Triangle(Float, Float)      // 追加した

fn area(s: Shape) -> Float = match s {
  Circle(r) => 3.14159 * r * r,
  Rect(w, h) => w * h,
}                               // 直し忘れた
error[E010]: non-exhaustive match: missing Triangle(_, _)
  --> shape.almd:6:36
  hint: add arms for Triangle(_, _):
  Triangle(arg1, arg2) => _

失敗の扱いも同じです。失敗しうる呼び出しは Result を返し、それをどうするかを書かなければなりません。黙って捨てるのは、警告ではなくエラーです。

effect fn load(path: String) -> String = {
  let text = fs.read_text(path)     // 失敗しうるのに、どこにもそう書いていない
  text
}
error[E041]: implicit propagation of this binding's value was removed —
this value is a Result
  --> load.almd:4:14
  hint: Write `expr!` to propagate, or consume the Result as a value
  (`??`, `?`, match ok/err).

0.69.0 のコンパイラ出力です。一部を省略しています。

直すのは1文字です：fs.read_text(path)!。大事なのは、書き手が決めなければならなかったこと、そしてその決定がソースに見える形で残ることです。

07 — 1つのソース、2つのターゲット

同じソースからネイティブと WebAssembly を作り、同じ出力を求めます。

ネイティブのビルドはRustを経由します。WebAssemblyは、LLVMを挟まずにコンパイラが直接出力します。hello world は 325 バイトの .wasm ファイルになります。

バックエンドが2つあれば、食い違うことがあります。だから、外から観測できる約束はすべて「契約」として書き出してあります。今は454個あり、一つ一つが実行できる証拠に結びついています。CIは1,038本のプログラムを両方のターゲットで実行し、標準出力・標準エラー・終了コードを比べます。3つ目の実行系として、コード生成の前の段階でプログラムを実行するインタプリタも判定に加わります。

この比較は、文書に書かれた条件のもとで成り立ちます。乱数、時計、プラットフォームの細部には、それぞれ範囲を区切った契約があります。インタプリタは、実行できない17本については判定を棄権します。

08 — ほかに入っているもの

デモではなく、ひとそろいの言語です。

標準ライブラリ

51モジュール、1,324関数。Almide 自身で書かれています。今ある中でいちばん大きな Almide プログラムです。

ツールは1つのバイナリに

almide test、fmt、check、fix、explain。テストは test ブロックとして、コードのすぐ隣に書きます。

明示的なエフェクト

effect fn は、外の世界に触れるコードの印です。失敗の伝搬は、必ず ! で書きます。

構造化された並行処理

fan は、ネイティブではスレッドで処理を走らせ、Wasm でも同じ出力順になります。

検証できるリリース

リリースの配布物はすべて Sigstore で署名されています。インストーラはチェックサムを確かめ、署名を確認できなければインストールしません。

実際のプログラムに使われている

コーディングエージェント、パーサ、2D/3D レンダラ、ターミナルエミュレータ。2026年9月の時点で、144の公開リポジトリに Almide のソースがありました。一覧を見る（英語）。

09 — まだできていないこと

完成していません。そこははっきり言っておきます。

  • コンパイラ全体は証明されていません。証明が覆っているのは、検査器とそのモデルです。
  • ネイティブのビルドは検証器を実行しません。既定では検証済みのレンダラをまず試し、それがまだ扱えないプログラムは通常のコード生成に戻ります。
  • 手元のマシンで動くのは、4つの検査器のうち1つだけです。ほかの3つは、CIでテスト用のプログラムに対して動きます。検証器が入っていなければ、Wasmのビルドは検査なしで通ります。
  • 証拠が部分的な場合があります。プログラムの一部しか覆っていない証明書も通します。component 出力はこの方法では検査されません。
  • 所有権の証拠が、生成されたバイト列と対応しているかは、まだ信頼に置いています。境界チェックと初期化の証拠は、バイト列と突き合わせています。所有権はまだです。
  • すべての検査を通ったプログラムでも、計算結果が間違っていることはあります。この仕組みは、ロジックが正しいかどうかを見るものではありません。
  • エージェントがRustやTypeScriptよりAlmideをうまく書ける、とは示せていません。最初の計測は、強いモデルではどの言語でもほぼ100%になり、何も分かりませんでした。
  • 1.0 より前です。既知のバグがあり、これからも変わります。

何が証明済みで、何が信頼に置かれているだけなのかの全体は、リポジトリにあります：proven vs trusted（英語）。

10 — どう作ったか

AIエージェントと一緒に作りました。それが出発点です。

コンパイラはRustで書かれていて、書くのにAIエージェントをたくさん使いました。先にそう言っておきます。そうやって作られたものは見たくない、という人もいるはずで、それはもっともだと思うからです。

ただ、このプロジェクトがこういう形をしている理由も、そこにあります。エージェントがコンパイラを書くのなら、自分が読んだことを根拠に保証することはできません。だからコンパイラは証拠を出さなければならず、別の何かがその証拠を検査しなければならない。これは、エージェントを使う人すべてが、自分のコードについてこれから抱える問題と同じです。Almideは、その問題に公開の場で取り組んでいるものです。

11 — 試す

どこで壊れるか、見てください。

Playground はブラウザで動き、インストールは要りません。macOS か Linux にコンパイラと検証器を入れるには：

curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/almide/almide/main/tools/install.sh | sh

インストーラは、リリースの署名を確かめるために GitHub CLI（gh）を必要とします。Windows とソースからのビルドは README にあります。

Playground →ブラウザで Almide を書いて実行する。 GitHub →コンパイラ、証明、テスト、issue。 ドキュメント →言語ガイドと標準ライブラリ。

Almide はオープンソースです。試してみて何か壊れたら、issue を送ってもらえるのがいちばん助かります。

このページの文章は、AIアシスタントで下書きし、リポジトリと照らして確かめたものです。
